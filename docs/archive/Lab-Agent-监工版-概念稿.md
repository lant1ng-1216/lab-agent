## 1. 它是什么 / 不是什么

**它是什么**:
- **配对模式**：Lab = 监工桌面端；Coding 可用外部主流 AI Agent 桌面端（Cursor 等）——视觉上双桌面窗 + 连线。
- **单用模式**：Lab 一分为二 —— **监工 loop** + **Coding loop**，两个桌面窗都由 Lab 提供。
- 职责上：**监工角色不写代码**；**Coding 半边负责执行**。

**它不是什么**:不是又一个聊天框;不是共享同一会话上下文的"第二窗口";不是 IDE 内嵌面板。

---

## 2. 两个核心论断

### ① 对齐的是开发者的"感受"
Lab = 全程跟随的意图锚。

### ② 讨论必须与执行隔离 + 单向可读

| 方向 | 是否允许 | 原因 |
|---|---|---|
| Coding → Lab | **可读**（只读镜像 / 订阅） | 意图跟随 + 实时监控 |
| Lab → Coding | **不可写共享、不塞聊天史** | 讨论不污染执行上下文 |
| 共享同一 transcript | **禁止** | — |
| 显式指令通道 | **允许** | PRD / 验收打回 / 确认后的指令 |

## 3. 形态表达（桌面 App ↔ 桌面 App）

- 两个 **OS 级桌面窗口**（Electron `BrowserWindow`）
- 第三层：**全屏透明 always-on-top overlay** 画白色连接线
- 线样式：正常白色、适度细（约 1.75px）、不发光炫彩
- **拖拽自适应**：窗口 `move/resize` → 重算路径
- **动态对向锚点**：按两窗中心相对位置选面对面的边（左/右/上/下），避免对调后绕线穿窗

预览底稿：`docs/archive/previews/overlay-link-demo.html`

## 4. 真双 loop 架构（一期实现）

```
用户
 ├─ 监工窗 ── SupervisorLoop ── DeepSeek
 │              ↑ 只读镜像
 │              │
 └─ Coding窗 ── CodingLoop ── DeepSeek
                 ↑ 仅显式指令（PRD / instruction / reject…）
```

对照基座（学架构、不绑死）：Claude Code / OpenAI Agents SDK / DeepSeek harness 思路 → Lab 自研 runtime。

## 6. 红线

- 上下文隔离 + 单向镜像
- 对齐 ≠ 附和
- 付费内容不进模型；默认本地
- 成本：记录/比对尽量规则化，关键节点才调 LLM
